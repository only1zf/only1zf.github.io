Locale 笔记

测试环境：macOS 26.6 / Darwin 25.6.0 (arm64)，验证时间 2026-07-31 11:29 UTC+8， 复核 2026-07-31 12:15 UTC+8（第八节脚本全节重跑，输出与基准逐字一致）。 本文所有结论均为该环境实测，非理论推导；标注「未复现」的条目请勿当作事实引用。

一、LC_* 分类体系​

locale 不是单一开关，而是六个独立分类：

分类管什么
LC_COLLATE字符串排序与比较：sort 顺序、strcoll()、正则/glob 的 [a-z] 范围
LC_CTYPE字符分类与大小写：isalpha、toupper、多字节解码
LC_NUMERIC小数点、千分位分隔符
LC_MONETARY货币符号
LC_TIME日期时间格式
LC_MESSAGES程序消息语言

优先级​

LC_ALL  >  各个 LC_xxx  >  LANG
  • LC_ALL 是「一刀切」，设了它就碾压全部六个分类
  • LANG 是兜底默认值，优先级最低，允许子程序用 LC_xxx 覆盖

二、C.UTF-8 vs en_US.UTF-8 实测​

printf 'banana\nApple\ncherry\nBanana\napple\n_underscore\n' > s.txt
LC_ALL=C.UTF-8     sort s.txt
LC_ALL=en_US.UTF-8 sort s.txt
维度C.UTF-8en_US.UTF-8
排序 LC_COLLATEApple Banana _underscore apple banana cherry（码点序）_underscore apple Apple banana Banana cherry（语言学序）
多字节 LC_CTYPE中文abc = 5 字符 / 9 字节5 字符 / 9 字节（相同）
千分位 LC_NUMERIC12345671,234,567
货币符号空$
%c 时间 LC_TIMEFri Jul 31 11:29:13 2026相同（macOS 上无差异；glibc 上有差异）

排序是两者唯一的重大差异。

一句话概括：C.UTF-8 = 纯 C 的中立行为 + UTF-8 字符识别能力。

三、坑一：纯 C 破坏多字节​

for L in C.UTF-8 en_US.UTF-8 C; do
  printf '%-12s 字符数=%s 字节数=%s\n' "$L" \
    "$(printf '中文abc' | LC_ALL=$L wc -m | tr -d ' ')" \
    "$(printf '中文abc' | LC_ALL=$L wc -c | tr -d ' ')"
done
locale字符数字节数
C.UTF-859
en_US.UTF-859
C99

纯 C 按字节计数，会真正破坏中文。C.UTF-8 正是为修掉这个缺陷而生，在字符处理上与 en_US.UTF-8 完全等价。

四、坑二：C.UTF-8 排中文是乱的​

printf '张三\n李四\n王五\n陈六\n赵七\n' > cn.txt
locale结果说明
C.UTF-8张三 李四 王五 赵七 陈六Unicode 码点序，对人无意义
en_US.UTF-8张三 李四 王五 陈六 赵七也不是拼音序
zh_CN.UTF-8陈六 李四 王五 张三 赵七拼音序 chén lǐ wáng zhāng zhào，正确

任何面向人展示的有序列表都不能用 C.UTF-8。

五、坑三：LC_ALL 碾压 LC_COLLATE​

设了 LC_ALL 之后再单独设 LC_COLLATE 是无效的：

LC_ALL=C.UTF-8 LC_COLLATE=zh_CN.UTF-8 sort cn.txt
# → 张三 李四 王五 赵七 陈六    码点序，LC_COLLATE 被忽略

env -u LC_ALL LC_COLLATE=zh_CN.UTF-8 sort cn.txt
# → 陈六 李四 王五 张三 赵七    拼音序，生效

需要临时改排序规则时，必须先 unset LC_ALL：

env -u LC_ALL LC_COLLATE=zh_CN.UTF-8 your-script

六、坑四：[a-z] 匹配大写（macOS 未复现）​

glibc 上 en_US.UTF-8 的 collation 是 aAbBcC 交错，导致 [a-z] 会匹配到大写字母。

本机实测未复现：

echo B | LC_ALL=en_US.UTF-8 grep -q '[a-z]'   # 不匹配
echo B | LC_ALL=en_US.UTF-8 rg   -q '[a-z]'   # 不匹配

原因：

  • BSD libc 的范围表达式按码点处理，不查 collation 表
  • rg 用 Rust regex，范围是固定的 Unicode 码点语义，本来就不受 locale 影响

该坑仅存在于 glibc（Linux）。脚本若要跑在 Linux CI 上仍需防范，而 LC_ALL=C 恰好是标准防法。

七、如何选​

开发 / 自动化 → C.UTF-8​

  • 排序为纯字节序，跨机器、跨系统版本可复现，CI 与本机结果一致
  • 无千分位，数字可直接喂给 awk / jq 做算术
  • 无本地化日期，日志时间戳格式稳定
  • 行业惯例：Debian 可复现构建、Go / Rust 工具链、大量 Dockerfile 都显式设 LC_ALL=C 或 C.UTF-8

面向人的输出 → 需要带 collation 表的 locale​

  • 中文列表用 zh_CN.UTF-8，英文用 en_US.UTF-8
  • 见第四节，码点序对人是乱序

可移植性提醒​

C.UTF-8 是较新 macOS 才加入的。本机可用：

$ locale -a | rg -i '^c\.'
C.UTF-8
$ LC_ALL=C.UTF-8 perl -MPOSIX -e 'print setlocale(LC_CTYPE, "")'
C.UTF-8

旧版 macOS 上 setlocale 会失败并回落到纯 C，中文随之损坏（见第三节）。跨机器分发的脚本需先探测。

八、完整测试脚本​

自包含、可直接粘贴运行，一次复现本文全部结论。依赖 rg 与 /usr/bin/perl。

#!/bin/bash
set -euo pipefail

WORK=$(mktemp -d)
trap 'rm -rf "$WORK"' EXIT
printf 'banana\nApple\ncherry\nBanana\napple\n_underscore\n' > "$WORK/en.txt"
printf '张三\n李四\n王五\n陈六\n赵七\n' > "$WORK/cn.txt"

section() { printf '\n=== %s ===\n' "$1"; }
row() { printf '%-14s ' "$1"; }

section "0. 环境与 locale 可用性"
uname -srm
sw_vers -productVersion 2>/dev/null || true
AVAILABLE=$(locale -a)
for L in C.UTF-8 en_US.UTF-8 zh_CN.UTF-8 C; do
  row "$L"
  printf 'locale-a=%s ' "$(rg -qiFx "$L" <<<"$AVAILABLE" && echo yes || echo NO)"
  printf 'setlocale=%s\n' \
    "$(LC_ALL=$L /usr/bin/perl -MPOSIX -e 'my $r=setlocale(LC_CTYPE,""); print defined $r ? $r : "FAILED"')"
done

section "1. 排序 LC_COLLATE（英文）"
for L in C.UTF-8 en_US.UTF-8; do
  row "$L"; LC_ALL=$L sort "$WORK/en.txt" | tr '\n' ' '; echo
done

section "2. 多字节 LC_CTYPE（纯 C 会破坏中文）"
for L in C.UTF-8 en_US.UTF-8 C; do
  row "$L"
  printf '字符数=%s 字节数=%s\n' \
    "$(printf '中文abc' | LC_ALL=$L wc -m | tr -d ' ')" \
    "$(printf '中文abc' | LC_ALL=$L wc -c | tr -d ' ')"
done

section "3. 中文排序（只有 zh_CN 给出拼音序）"
for L in C.UTF-8 en_US.UTF-8 zh_CN.UTF-8; do
  row "$L"; LC_ALL=$L sort "$WORK/cn.txt" | tr '\n' ' '; echo
done

section "4. 数字与货币 LC_NUMERIC / LC_MONETARY"
for L in C.UTF-8 en_US.UTF-8; do
  row "$L"
  printf '千分位=%s ' "$(LC_ALL=$L /usr/bin/printf "%'d" 1234567)"
  LC_ALL=$L locale -k thousands_sep currency_symbol | tr '\n' ' '; echo
done

section "5. 时间 LC_TIME（macOS 上两者相同）"
for L in C.UTF-8 en_US.UTF-8; do row "$L"; LC_ALL=$L date '+%c'; done

section "6. LC_ALL 碾压 LC_COLLATE"
row 'LC_ALL+COLLATE'; LC_ALL=C.UTF-8 LC_COLLATE=zh_CN.UTF-8 sort "$WORK/cn.txt" | tr '\n' ' '
echo '  <- 码点序，LC_COLLATE 被忽略'
row 'unset LC_ALL';  env -u LC_ALL LC_COLLATE=zh_CN.UTF-8 sort "$WORK/cn.txt" | tr '\n' ' '
echo '  <- 拼音序，生效'

section "7. [a-z] 是否匹配大写 B（glibc 才有此坑）"
for L in C.UTF-8 en_US.UTF-8; do
  row "$L"
  printf 'grep=%s ' "$(echo B | LC_ALL=$L grep -q '[a-z]' && echo 匹配 || echo 不匹配)"
  printf 'rg=%s\n'   "$(echo B | LC_ALL=$L rg   -q '[a-z]' && echo 匹配 || echo 不匹配)"
done
